# Приёмка MVP

## Пользовательский путь

1. `/start` → переслать сообщение неизвестного клиента.
2. Создать клиента → «Дозаказ» → «Новый проект» → название → сумма 5000.
3. Открыть проект → «Данные и заметки» → добавить поле «Домен».
4. Открыть задачу → «В работе» → «Выполнено».
5. Карточка клиента → услуги → добавить «Сервер», 5000, дата начала текущего месяца.
6. Счёт: итог 10000; повторно открыть — итог остаётся 10000.
7. Выставить счёт через подтверждение.
8. Оплата 4000 → частично оплачен, долг 6000.
9. Оплата 6000 → оплачен, долг 0.
10. Проверить неизменность выставленного счёта при изменении источника
    (автоматический тест изменяет источник напрямую; интерфейс блокирует правку цены).
11. Создать и завершить ещё одну задачу в том же месяце на 19500.
12. «Клиент → Счета»: новый черновик на 19500, без повторного начисления сервера.
13. Выставить второй счёт, открыть оба через «История счетов», проверить разные номера.
14. Внести оплату второго счёта; первый остаётся оплаченным, месячная сумма — 29500.
15. При нулевом долге нет кнопки оплаты. Старая кнопка не начинает ввод платежа.
16. Нулевой платёж по неоплаченному счёту даёт понятную ошибку; корректная сумма
    принимается в том же диалоге. Пустой черновик выставить нельзя.

`tests/test_bot_flow.py::test_full_forward_to_paid_invoice` проходит весь финансовый
сценарий через диспетчер и БД. Порядок добавления поля не влияет на счёт.
Транспорт Telegram подменён, поэтому успешность живой отправки и внешний вид
в Telegram этот тест не подтверждает.

## Объединение отдельных позиций

1. Создать у одного клиента счёт A с позициями 19500 и 5000, счёт B — на 1000.
2. Выставить оба без оплаты. B → «Позиции» → «Объединить позиции».
3. Выбрать только позицию A на 19500; продолжить, проверить итог 20500, подтвердить.
4. Новый общий счёт — 20500, отдельный счёт остатка A — 5000. Общий долг — 25500.
5. Исходные A и B доступны в истории со статусом «Заменён при объединении»;
   их суммы сохранены, кнопки оплаты нет, «Новые счета» открывает результаты.
6. Повторное подтверждение не создаёт дублей. Оплатить общий счёт — долг остаётся 5000.
7. На нескольких страницах выбрать и снять галочки; отмена не меняет счета.
8. Счёт с частичной оплатой недоступен для объединения; повторная генерация услуг
   после объединения не начисляет их ещё раз.

## Дополнительные проверки

- Известный отправитель повторно использует карточку; скрытый — выбирается вручную.
- Повторная пересылка известного сообщения предупреждает о существующей задаче.
- Две ручные задачи подряд создаются независимо.
- Пользовательские `<`, `>` и `&` экранируются при выводе HTML.
- `/cancel` сбрасывает диалог. Старые кнопки показывают понятное сообщение.
- Оплата сверх долга не сохраняется; можно ввести корректную сумму без перезапуска.
- Архив проекта сохраняет заметки и историю; архивные карточки находятся поиском.
- Регулярные услуги можно изменить/отключить; исторические счета не меняются.
- Напоминание адресовано только владельцу, отмена предотвращает доставку.
- Два одновременных платежа не создают переплату; один ключ действия записывается один раз.
- Одновременные DONE и пересборки не дублируют позиции; выставление/правка сериализуются.
- ORM соответствует миграциям PostgreSQL (`alembic check`).

## Что требуется для живой приёмки

Для отдельной установки заполните локальный `.env` с `BOT_TOKEN` и
`OWNER_TELEGRAM_ID`, выполните `docker compose up -d --build` и пройдите шаги выше.
Секреты не хранятся в Git. Автотесты не заменяют визуальную приёмку владельцем
в Telegram; тестовые финансовые записи в рабочую базу не добавляются.
